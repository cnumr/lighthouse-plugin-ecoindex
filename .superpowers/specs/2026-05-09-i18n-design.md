# Design — Internationalisation EN/FR (i18n)

Date: 2026-05-09  
Statut: approuvé

---

## Objectif

Ajouter le support multilingue EN/FR sur les 3 packages du monorepo :
- `ecoindex-lh-cli` — flag `--lang`, strings CLI
- `ecoindex-lh-courses` — propagation locale, strings console
- `ecoindex-lh-plugin-ts` — audits Lighthouse, plugin config

Le paramètre de langue se propage de bout en bout :
```
CLI: --lang fr
  └→ cliFlags['lang']                          (ecoindex-lh-cli)
       └→ CliFlags.lang → getLighthouseConfig() (ecoindex-lh-courses)
            └→ settings.locale = 'fr'           (Lighthouse)
                 └→ context.settings.locale      (ecoindex-lh-plugin-ts)
                      └→ str_(UIStrings.xxx)     (chaque audit)
```

**Défaut `'en'` garanti à chaque couche** — aucun consommateur ne casse si `lang` est absent.

---

## Décisions clés

| Sujet | Décision |
|---|---|
| Approche plugin core | Lighthouse natif : `createIcuMessageFn` + `registerLocaleData` |
| Approche CLI + courses | Plain TS objects `{ en, fr }` + `t(key, lang = 'en')` |
| Scope audits | Tous : 8 principaux + ~35 rweb-* + 4 BP custom + plugin.ts |
| Strings traduites | `title`, `failureTitle`, `description`, `displayValue` (ICU pour les dynamiques) |
| Titres rweb-* | Traduire la partie description : `"RWEB_0031 - Print CSS"` → `"RWEB_0031 - CSS d'impression"` |
| Génération des 50 fichiers | Script one-shot `i18n-extract-patch.ts` (patch .ts + génère JSON) |
| Traductions FR | Assurées par l'assistant (fr.json + strings.ts) |
| Test couverture | Script Node.js standalone `check-i18n-coverage.ts` + `pnpm check:i18n` |
| Défaut langue | `'en'` à tous les niveaux (yargs default, paramètre optionnel, fallback Lighthouse) |

## Package 1 : `ecoindex-lh-cli`

### Nouveaux fichiers
```
apps/ecoindex-lh-cli/src/i18n/strings.ts
```

### Modifications
- `cli-flags.ts` : ajout option `--lang` (choices: `'en' | 'fr'`, default: `'en'`)
- Descriptions yargs et messages d'erreur auth passent par `t(key, lang)`

### Pattern `strings.ts`
```typescript
type Lang = 'en' | 'fr'

const strings = {
  en: {
    'auth.error.url': 'Authentication option error: url is undefined.',
    // ...
  },
  fr: {
    'auth.error.url': "Erreur d'authentification : url non définie.",
    // ...
  },
}

export const t = (key: keyof typeof strings['en'], lang: Lang = 'en'): string =>
  strings[lang]?.[key] ?? strings['en'][key]
```

## Package 2 : `ecoindex-lh-courses`

### Nouveaux fichiers
```
libs/ecoindex-lh-courses/src/i18n/strings.ts
```

### Modifications
- `types/index.d.ts` : `lang?: 'en' | 'fr'` dans l'interface `CliFlags`
- `commands.ts` : `getLighthouseConfig()` reçoit `lang` et injecte `settings.locale = lang ?? 'en'`
- `run.ts`, `printer.ts`, `commands.ts` : messages console passent par `t(key, lang)`

### Pattern `getLighthouseConfig()`

`lang` est lu depuis `cliFlags['lang']` dans `run.ts` et transmis à `getLighthouseConfig()` :

```typescript
function getLighthouseConfig(isWarm, stepName, onlyCategories, userAgent, lang?: 'en' | 'fr') {
  return {
    config: {
      settings: {
        ...
        locale: lang ?? 'en',
      },
    },
  }
}
```

## Package 3 : `ecoindex-lh-plugin-ts`

### Nouveaux fichiers
```
libs/ecoindex-lh-plugin-ts/src/locales/en.json     ← source de vérité (généré par script)
libs/ecoindex-lh-plugin-ts/src/locales/fr.json     ← traductions FR (remplies par l'assistant)
scripts/i18n-extract-patch.ts                       ← script one-shot de génération/patch
scripts/check-i18n-coverage.ts                      ← vérification couverture FR vs EN
```

### Script `i18n-extract-patch.ts` (one-shot, jetable après usage)

Séquence d'exécution :
1. Parcourir tous les `.ts` dans `src/audits/` et `src/audits/bp/`
2. Extraire les strings hardcodées (`title`, `failureTitle`, `description`, `displayValue` statiques)
3. Patcher chaque fichier : insérer l'import `createIcuMessageFn`, la const `UIStrings`, remplacer les strings par `str_(UIStrings.xxx)`
4. Écrire `locales/en.json` (strings agrégées) et `locales/fr.json` (clés identiques, valeurs vides)

### Pattern résultant dans chaque audit

Pour les `displayValue` dynamiques, ICU est utilisé avec `{count}` :

```typescript
// en.json : "audits/bp/rweb-print-css.js | displayValue": "Print CSS count: {count}"
// fr.json : "audits/bp/rweb-print-css.js | displayValue": "Nombre de CSS print : {count}"

const UIStrings = {
  displayValue: 'Print CSS count: {count}',
}
// Utilisation :
displayValue: str_(UIStrings.displayValue, { count: stylesheets.length })
```

```typescript
import { createIcuMessageFn } from 'lighthouse/core/lib/i18n/i18n.js'

const UIStrings = {
  title: 'Ecoindex revealant metrics.',
  failureTitle: 'Ecoindex, your page could be improved.',
  description: 'The EcoIndex score evaluating the environmental impact of the page.',
}
const str_ = createIcuMessageFn(import.meta.url, UIStrings)

// Dans meta() :
static get meta() {
  return {
    title: str_(UIStrings.title),
    failureTitle: str_(UIStrings.failureTitle),
    description: str_(UIStrings.description),
    // ...
  }
}
```

### Format des clés JSON (convention Lighthouse)
```json
{
  "audits/ecoindex-score.js | title": "Ecoindex revealant metrics.",
  "audits/ecoindex-score.js | failureTitle": "Ecoindex, your page could be improved.",
  "audits/bp/rweb-print-css.js | title": "RWEB_0031 - Print CSS",
  "audits/bp/rweb-print-css.js | failureTitle": "RWEB_0031 - No print css implemented."
}
```

### `plugin.ts` — enregistrement de la locale FR
```typescript
import { registerLocaleData } from 'lighthouse/shared/localization/format.js'
import frLocale from './locales/fr.json' assert { type: 'json' }

registerLocaleData('fr', frLocale)
```

Les groupes et la catégorie suivent le même pattern `UIStrings` + `str_()`.

### Script `check-i18n-coverage.ts`
```typescript
// Lit en.json et fr.json, compare les clés
// Affiche les clés manquantes en FR
// Exit code 1 si manques (bloquant en CI)
```

Lancé via `pnpm check:i18n` dans le package plugin.

---

## Phases d'implémentation

### Phase 0 — Propagation `lang` (prérequis)
1. `ecoindex-lh-cli` : option `--lang` dans yargs + `t()` sur les strings CLI
2. `ecoindex-lh-courses` : `lang` dans `CliFlags`, `getLighthouseConfig()` → `settings.locale`, `t()` sur les strings console

### Phase 1 — Infrastructure plugin
1. Script `i18n-extract-patch.ts` → patch les 50 fichiers + génère `en.json` / `fr.json` skeleton
2. Remplissage de `fr.json` (toutes les traductions, par l'assistant)
3. `registerLocaleData('fr', frLocale)` dans `plugin.ts`
4. `UIStrings` + `str_()` sur catégorie et groupes dans `plugin.ts`

### Phase 2 — Validation
1. Script `check-i18n-coverage.ts` + `pnpm check:i18n`
2. Test E2E : `ecoindex-lh-cli collect --lang fr`

---

## Critères de succès

- `ecoindex-lh-cli collect --lang fr` produit un rapport Lighthouse avec toutes les strings en français
- `pnpm check:i18n` passe sans erreur (100% des clés EN couvertes en FR)
- Sans `--lang`, tout fonctionne en anglais comme avant (aucune régression)
- Fallback EN automatique si une clé FR est absente
